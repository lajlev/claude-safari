# Send to Claude (Safari extension)

A small Safari Web Extension for macOS that sends the current page (or your selection) to Claude, either as a **new chat** or **added to the conversation you already have open**.

## Usage

| Action | New chat | Add to current chat |
| --- | --- | --- |
| Toolbar button | opens a small popup; click **New chat** | click **Add to current chat** |
| Keyboard | **⌘E** | **⇧⌘E** |

The popup shows each button's shortcut and where it will go ("Reuses your Claude tab", "Adds to: <chat title>"). When no claude.ai conversation is open, "Add to current chat" says *No open chat — will start a new one* and does exactly that. On claude.ai itself both buttons are disabled with a notice, and the shortcuts do nothing.

- **New chat** loads `claude.ai/new` in the Claude tab and pastes the context there. A half-typed message in that tab is lost.
- **Add to current chat** does not navigate. It inserts the context into the composer of the conversation that's already open, appended after anything you've typed (separated by a blank line), and focuses it. If that tab has no composer (e.g. a settings page), it falls back to a new chat.

Neither mode sends the message.

### Which Claude tab is used

Any claude.ai tab in any Safari window counts, including ones you opened yourself. In order of preference:

1. The tab the extension used last time.
2. A tab in the window the extension opened (its active tab first).
3. Any other claude.ai tab, most recently used first (when Safari reports `lastAccessed`), else the first one found.
4. None: a new window opens on the right 1/3 of the screen.

### Window tiling

- Claude tab in **another window**: your window goes to the left 2/3 and the Claude window to the right 1/3, then the Claude window is focused.
- Claude tab in the **same window** as the page: that tab is just activated; nothing is resized.

## What gets sent

1. Takes the current tab's title, URL and your selected text (as plain text). With no selection it converts the page's main content to **Markdown**: Mozilla Readability picks the article (run on a copy of the page, never the live DOM), then Turndown converts it with ATX headings, `-` bullets, fenced code blocks (language kept from `language-xx`/`lang-xx` classes), GFM tables, absolute link and image URLs, and a byline line when Readability finds one. Scripts, styles, iframes, SVG, forms, buttons, empty links, 1×1 tracking pixels and `data:` images are dropped. If Readability finds nothing or any step fails, it falls back to the old plain-text extraction (prefers `<article>`/`<main>`, drops nav/footer/scripts/styles). The result is capped at 50,000 characters, cut at a paragraph or line boundary (an open code fence is closed), with a note when it was cut.
2. Picks a Claude tab and tiles windows as described above.
3. Puts the context into the Claude composer **without sending it**, formatted like this:

   ```
   Context from: <title>
   <url>

   <selection text, or page Markdown>

   ---
   ```

   The cursor is left at the end so you can type your question. If the insert fails, the text goes to the clipboard and a toast says "Page context copied — press ⌘V". If Safari blocks the clipboard write, the toast shows a **Copy it** button instead.

Manifest V3 and plain JS, with no build step for the extension itself.

```
extension/            the web extension (manifest.json, background.js, claude-inject.js, popup.html/js/css, icons/)
extension/vendor/     third-party libraries injected into the page (see below)
tools/make-icons.py   regenerates icons/ (needs Pillow)
build.sh / Makefile   generate the Xcode wrapper app and build it
xcode/, build/        generated by build.sh (safe to delete)
```

## Build

You need Xcode.app. It does not have to be the selected developer directory: `build.sh` finds Xcode and sets `DEVELOPER_DIR` itself.

**One-time step:** accept the Xcode license. Until you do, `xcrun` and `xcodebuild` refuse to run:

```sh
sudo DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -license accept
sudo DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -runFirstLaunch
```

Opening Xcode.app once and accepting the license there also works.

Then build:

```sh
./build.sh        # or: make
make check        # JS syntax + manifest check
make open         # launch the built app
make clean
```

`build.sh` runs `safari-web-extension-converter` (macOS only, Swift, `--copy-resources`) into `xcode/`. It then builds with `xcodebuild`, ad-hoc signed (`CODE_SIGN_IDENTITY=-`). The app ends up in `build/Build/Products/Release/Send to Claude.app`. Every build regenerates the project, because `--copy-resources` copies `extension/` into it.

If you would rather build in Xcode: open `xcode/Send to Claude/Send to Claude.xcodeproj`. For **both** targets (the app and the extension), set Signing & Capabilities > Team to *None* and Signing Certificate to *Sign to Run Locally*. Then choose Product > Run.

## Install / enable in Safari

1. Run the built app once (`make open`). It registers the extension with Safari, and you can quit it afterwards.
2. In Safari, open Settings > Advanced and turn on **Show features for web developers**.
3. From the **Develop** menu, choose **Allow Unsigned Extensions**. You need your password. Safari turns this off again every time it quits, so repeat it after each restart.
4. In Settings > Extensions, turn on **Send to Claude**.
5. Under the extension, click **Edit Websites…** and set **claude.ai** and **Other websites** to *Allow*. You can also grant access from the prompt the first time you use it.
6. If the toolbar button isn't visible, add it with View > Customize Toolbar.

## Shortcuts

| Command | macOS | Other platforms | Action |
| --- | --- | --- | --- |
| `send-page` | **⌘E** (`Command+E`) | `Ctrl+E` | New chat |
| `add-to-chat` | **⇧⌘E** (`Command+Shift+E`) | `Ctrl+Shift+E` | Add to current chat |

Both are `suggested_key`s in `commands` in `extension/manifest.json`. They work independently of the popup (with `action.default_popup` set, `action.onClicked` never fires, so the toolbar button only opens the popup).

**Conflict warning:** ⌘E is a built-in Safari shortcut (Edit > Find > *Use Selection for Find*), and pages can also bind ⌘E/⇧⌘E. Safari may refuse the suggested key or let its own shortcut win, in which case ⌘E does nothing for this extension. If so:

- Use the toolbar popup, or
- assign a key yourself where your Safari version allows it: Safari > Settings > Extensions (some versions let you set extension shortcuts there), or macOS System Settings > Keyboard > Keyboard Shortcuts > App Shortcuts for Safari (this only reaches commands that appear as menu items, so it may not help), or
- edit `commands` in `extension/manifest.json` and rebuild. Avoid ⇧⌘L, which toggles Safari's sidebar.

## How delivery works

Each send gets a unique id, so the content script never inserts the same send twice.

- **New chat:** the text is stored under `pending:<tabId>` (expires after two minutes, claimed once), the tab is navigated to `claude.ai/new`, and once it has loaded the content script is nudged. The content script also claims on load. Only the tab the extension targeted can claim it.
- **Add to current chat:** no navigation, so the content script is already running. The background sends the text straight to it with `tabs.sendMessage`. If no content script answers (e.g. the tab was open before the extension was enabled), it injects `claude-inject.js` with `scripting.executeScript` and retries; if that also fails, it falls back to the stored hand-off above. If the content script finds no composer within 3 s, the background switches to the new-chat flow.

## Limitations

- **Window tiling:** Safari may clamp or ignore some window sizes and positions. The screen size comes from the page you're on. On pages where extensions can't run scripts (Safari start page, `about:` pages, other extensions' pages), the tiling falls back to the current window's frame and only the title and URL are sent.
- **Composer injection** depends on claude.ai's current markup: a contenteditable ProseMirror editor. When claude.ai changes, the selectors in `claude-inject.js` may need updating. The fallback is clipboard plus ⌘V. Very long pastes may show up on claude.ai as an attached "pasted text" block instead of inline text.
- **New chat** reuses an existing Claude tab and loads `claude.ai/new` in it, so a half-typed message in that tab is lost. Use **Add to current chat** to keep it.
- Only the targeted Claude tab ever receives the text, and the stored hand-off expires after two minutes. Opening claude.ai yourself never triggers it.
- Conversation detection (for the popup hint) assumes conversation URLs look like `claude.ai/chat/<id>`.
- `claude.ai/new?q=…` prefill is not used and has not been tested.
- You have to be signed in to claude.ai. If you see a login page instead of the composer, the insert times out after 20 s and the clipboard fallback runs.
